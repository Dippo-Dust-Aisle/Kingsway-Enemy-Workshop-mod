# Known limits and evidence boundaries

- Editor writes are ordered within one page. Multiple tabs/servers or external text editors editing the same project do not have conflict merging; use one writer per project. GML source needs **Save callback file**. A browser/backend crash before a save succeeds can still lose unsaved work.
- This release supports one exact Windows Kingsway 1.2.1 data.win checksum. It does not infer compatibility from the displayed version string alone.
- Boss support is intentionally limited to the five reviewed adapters listed in BOSS-SUPPORT.md. Other unique endgame fights cannot be selected for installation. Demon King multipart support is conditional on its original four-slot spawner, not an assurance about every full-game ending.
- Native families share storage and cure behavior. There is no independent arbitrary custom-status engine. Native curse effects target the player, not enemy stats.
- The catalog is a static analysis with original expressions and certainty labels. Branch-dependent/random/runtime-calculated values are not guessed. Some base objects and internal references also appear in the catalog; consult their source before choosing them for advanced use.
- Native projectile spawning covers the ten reviewed adapters listed in EXPANSION.md. Stationary curses ignore outside entry. Special scripted boss choreography and room-specific fullscreen effects are not universally normalized by the ordinary movement scaling.
- GML extension scripts can be added; arbitrary manifest patches over existing vanilla events are blocked. Advanced callback code is trusted and cannot be behaviorally proven safe by compilation.
- A custom enemy is not added to the persistent vanilla bestiary. Limb/summon reward suppression includes native bestiary bookkeeping. Vanilla overridden slots retain their native identity and credit.
- Movement preview uses actual engine path samples and native speed/pause calculations, with numerical interpolation between samples. Random starts, variance and player state can differ in a live fight; equipment-dependent quickness should use the override when comparing. Native scripted boss movement is not reproduced in the preview.
- The isolated conformance suite runs its own fixture; Level Test and Random Fight are playable draft encounters, not proof of every authored conditional branch or an entire quest playthrough. The harness closes its own disposable runner once the final report is written, including when native teardown does not exit promptly after synthetic multi-encounter tests.
- The package requires the .NET 10 runtime and UndertaleModTool 0.9.2.0 in `Kingsway/UndertaleModdingTool`. It does not redistribute Kingsway game data, extracted graphics, saves, or a modified data.win.

- Fullscreen uses the current desktop display mode; the requested test resolution defines the render area. Windows may reduce a desktop-sized windowed client area to accommodate its frame (1366×768 requested produced 1366×749 in verification). Requested and actual sizes are included in the fight report. No operating-system resolution switch is made.
- Converted legacy random-placement overlap avoidance is best-effort (48 attempts), and a smooth transition can cross another window. The movement preview applies individual moves but does not simulate full combat branches or attack-speed actions. See [movement action semantics](MOVEMENT-ACTIONS.md).
- Attack Speed targets the acting combat enemy; player/hazard targets are rejected. Zero pauses charging but leaves an already-ready attack ready unless meter reset is selected.
- Waits have frame-level precision. Initial window/texture creation can stall the native runner; an action becomes runnable at its deadline and executes on the next available frame.
- Audio verification checks native playback state, conversion and cleanup. It does not assess subjective audibility on the user's speakers. WAV music conversion needs ffmpeg; an existing installation is discovered, with Ogg Vorbis import available without conversion.

- When attacked runs after native player attacks resolve, for surviving V2 enemies. It does not cover direct-damage spells/status ticks or cancel the current hit. Nullify still applies to a future outgoing attack; no healing is used to simulate cancellation. See [actions and reactions](ACTION-REACTIONS.md).
